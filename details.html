What broke, what I did, how I know it works

Each one is a real problem I ran into. The last line is how I check it, not a live result.

  1. Nothing changes by hand over SSH.

    What broke
    I’d fix something over SSH, forget about it, and the docs would quietly stop being true.
    What I did
    Configs, proxy routes and DNS records live in Forgejo now. Forgejo Actions runs Ansible to apply them, so every change has a commit, a pipeline run and a way back.
    How I know
    I run it again against a healthy host. If the playbook still wants to change something, that’s drift.

  2. AI agents don’t get a shortcut.

    What broke
    Agents and Renovate can open changes faster than I can read them, and a green checkmark is easy to trust too much.
    What I did
    They open pull requests like anyone else. A change only merges at the exact commit that passed checks and an independent review. Anything that would restart the box the agents run on waits for me.
    How I know
    After a merge I read the deploy run and the installed version back off the host. A passing pipeline alone doesn’t count.

  3. OS updates show up as a pull request every day.

    What broke
    Unattended upgrades change things with nobody watching, and when something breaks there’s no record of which version did it.
    What I did
    A bot opens a pull request every day with the exact package versions for every running container. When I merge it, each container gets a Proxmox snapshot right before its own update, one at a time.
    How I know
    Apply refuses a lockfile that isn’t from the latest merged batch and skips any container that changed since the plan. Then I read the installed versions back.

  4. Network zones that can’t see each other.

    What broke
    On a flat network, one bad service can reach everything else.
    What I did
    A MikroTik router sits at the edge with CrowdSec, and WireGuard only lets in peers I’ve approved. Guests live in management, core, edge and automation VLANs. The default is deny, and every allowed path is a router rule that went through review.
    How I know
    A canary check makes sure the blocked paths stay blocked. Blackbox probes internal sites over HTTPS, certificate expiry included.

  5. I’d rather have data than guess.

    What broke
    Without monitoring, every outage started with me guessing which layer broke.
    What I did
    Wazuh watches for security events, Prometheus collects host metrics, Blackbox probes endpoints, and Grafana is where I dig in. When a Grafana alert fires, it wakes the coordinating agent, which checks the live state before it tells me anything.
    How I know
    Probes want a real response, not just an open port, and a failed scrape counts as down. I proved the alert-to-agent path with a test alert.

  6. New containers sign themselves up for monitoring.

    What broke
    New containers are easy to forget, and a fresh one has no managed SSH access yet.
    What I did
    Once a new guest settles, Ansible reaches it through pinned Proxmox SSH, installs a Wazuh agent that matches the manager plus a node exporter, and writes only its own scrape target.
    How I know
    It only counts as enrolled when Wazuh shows the agent active, Prometheus has fresh data, and a second run changes nothing.

  7. One login for people, short-lived certs for scripts.

    What broke
    A password per app for people and long-lived keys for automation both mean one leak goes a long way.
    What I did
    Authelia handles sign-in, with OIDC when the app supports it and Caddy forward-auth when it doesn’t. Managed hosts take short-lived OpenBao SSH certificates checked against pinned host keys.
    How I know
    Before a host counts as managed, I test certificate SSH and sudo on it.

  8. The lab remembers things so I don’t have to.

    What broke
    Context kept getting lost between sessions, between people, and between AI agents.
    What I did
    Homelable keeps the inventory. OpenViking gives the agents memory that carries over between sessions. Ollama runs local models on a GPU passed through to a container. Changes still go through Git.
    How I know
    Notes are where I start, not proof. I check the live state before a change and update the docs after.

Two checks from the real code

Excerpts from my private infrastructure repo, as of October 2026. The nine discovery and target-selection unit tests passed locally when I put this together. It’s offline code, not a live health check, and no host was touched.

A reachable guest is not necessarily ready.

An installer can still be running after discovery thinks the guest is settled. This test marks the guest busy and makes sure onboarding keeps waiting.

def test_active_community_installer_defers_ready_guest(self):
    onboard.select([self.row], self.state, self.policy, 1000)
    self.assertFalse(
        onboard.select([{**self.row, "busy": True}], self.state, self.policy, 2000)[
            0
        ]
    )

Old discovery must not become a new target.

Before it publishes a scrape target, the selector re-checks the guest’s identity, that it’s running, and its address. If anything’s off, it skips it.

row = current.get(key)
if (
    not row
    or row["identity"] != h["identity"]
    or row["status"] != "running"
    or h["address"] not in row.get("addresses", [])
